# v3.50 意图层设计（任务书 + 钉住注入 + 终审判据绑定 + 停止线自生成 + 低置信拦截 + 主人词典种子）

- 状态：设计稿（2026-10-22，hourly 排期第 1 步产出）
- 依据：`~/workspace/learning-loop-SPEC.md` 第二节（意图层）+ 第五节落地顺序第 1 项 + 第六节验收口径
- 用户定调：笨在工作流不在模型（模型档位不动）；意图层纯结构与提示词层，收益最大、风险最小
- 版本位：v3.50（versionCode 162），整包（核心回路改动不用热补丁）

## 一、现状锚点（动刀前先看清）

1. `Thinker.plan()` 只在 `MainActivity`（App 通道）调用，TG/远控不走——所以任务书生成**不能**复用 Thinker 调用点，必须下沉到三端共享的 `AgentLoop.run()` 里。
2. `AgentLoop.runSession()` 用 `messages` JSONArray 做 DSH 式会话状态；`compactMessages()` 在 >40 条时压缩中段、只保留首 2 + 末 26——任务书若只放在首轮 system prompt 里，长任务会被挤到"已省略"区。这就是 SPEC 说的"钉在上下文之外"的工程含义。
3. 终审 `Supervisor.review(client, goal, workerSaid, history, finalScreen, finalShot)` 已有"按目标对象状态核对，不按工作量核对"等判据，但判据是写死在 prompt 里的通用文本，没有"本次任务的完成判据"这个输入。
4. 停止线现状是硬编码特例：`hasClaimEvidence`/`hasUpsell`/`adBudget` 只治领取/奖励类（p1/p2 补丁）。v3.50 要把它一般化为"任务书长出停止线"，旧硬编码保留做兜底。
5. 共享经验注入走 `SharedMemory.relevantExperience()` 进 `conversationContext`，已有"内部参考头·禁入最终答案"（p4）。任务书是另一块注入，互不干扰，但拼 prompt 时顺序固定：任务书钉住块 > 技能卡 > 经验 > 用户记忆。
6. 词典现状：无。`UserMemory` 是 key-value 偏好记忆（加密 prefs），词典是另一类东西（个人语义映射），单独建。

## 二、TaskBook 数据结构

```java
public class TaskBook {
/** 任务对象：如"汽水音乐今日免费听歌时长" */
public String target = "";
/** 动作：领取 / 打开 / 查询 / 设置 / 播放… */
public String action = "";
/** 完成判据：核心字段。如"界面出现「领取成功/已领取」字样" */
public String criteria = "";
/** 停止线：判据达成后必须做的事 + 目标外链条识别 */
public List<StopLine> stopLines = new ArrayList<>();
/** 禁区：不许做的事。如"不许点开会员充值页" */
public List<String> forbidden = new ArrayList<>();
/** 置信度 0~1：模型对自己理解的把握 */
public double confidence = 0.5;
/** 置信度低的原因（一句话，给澄清问题用） */
public String doubt = "";

public static class StopLine {
/** 触发信号，如"界面出现「领取成功」" */
public String signal = "";
/** 触发后动作，如"立即收尾报告，不再看广告" */
public String action = "";
}

/** 钉住块：每轮注入的紧凑文本（见第四节） */
public String describe();
/** 从 LLM JSON 解析 */
public static TaskBook fromJson(String json);
/** 零 token 本地兜底：关键词启发式（见第三节） */
public static TaskBook fromHeuristic(String goal);
}
```

字段全部纯 Java + org.json（学 TaskPlan 的样子），无 Android 依赖，可 JVM 单测。

## 三、生成：开跑前一次调用，共享层

位置：`AgentLoop.run(goal, maxSteps)` 内、`runSession` 之前。三端（App/TG/远控）都走 `run()`，一次落地三端生效。

```java
TaskBook book = TaskBook.generate(llm, goal, MasterDict.describeForPrompt(ctx));
if (book == null) book = TaskBook.fromHeuristic(goal); // LLM 失败兜底
```

`generate` 是一次短 LLM 调用，prompt 要点：

- 输入：用户原句 + 主人词典全文 + 任务类型先验（领取类/操作类/查询类/问询类）。
- 输出纯 JSON：`{"target":"…","action":"…","criteria":"…","stop_lines":[{"signal":"…","action":"…"}],"forbidden":["…"],"confidence":0.8,"doubt":""}`。
- 明确要求：criteria 必须是**可观测的手机界面/系统状态**（出现某文案、某开关变为开、某文件生成），不许写"任务完成"这种空话；stop_lines 至少一条"判据达成后的收尾动作"；领取/奖励类必须有一条"「再看N个提前得明日」是目标外链条，出现即收尾"。
- confidence 标尺写进 prompt：对象明确且可达 ≥0.7；对象多义/指代不明 ≤0.4 并在 doubt 写清卡在哪。

`fromHeuristic` 规则（零 token，不烧用户 key 也能跑）：

- 含"领取/免费/奖励/时长" → action=领取，criteria="界面出现「领取成功/已领取」字样"，stopLines=领取成功即收尾 + 链条推销识别。
- 含"打开/启动" → action=打开，criteria="目标应用进入前台（dumpsys / 截屏确认）"。
- 含"查/多少/是什么" → action=查询，criteria="拿到答案文本"。
- 其它 → action=执行，criteria="按用户原句字面达成"，confidence 降 0.2。
- forbidden 默认种子：["不许做与目标无关的充值/订阅", "任务结束回手机桌面"]（铁律进禁区，防忘）。

token 账：每任务多一次短调用（约 300~500 token），相对原来 Thinker 规划调用量级相当，可接受。启发式兜底保证离线/失败不断链。

## 四、钉住注入：book 活在 messages 之外

- `AgentLoop` 新增字段 `private TaskBook taskBook;`，`run()` 生成后持有。
- 每轮给模型发消息前（`runSession` 的 round 循环里组装 user content 处），把 `book.describe()` 以独立 user 段拼在**本轮 user 消息最前面**：

```
📌 任务书（每轮重申，以此为准）：
对象：汽水音乐今日免费听歌时长｜动作：领取
完成判据：界面出现「领取成功/已领取」字样
停止线：①出现领取成功→立即收尾报告，不再看广告；②出现「再看N个提前得明日」→目标外链条，点坚持退出并收尾
禁区：不许点会员充值页；任务结束回手机桌面
主人词典：clash=Clash_For_Magisk模块(非App)；领时长=汽水/酷狗既定路径；音乐任务收尾停播清后台
```

- 为什么不在 system prompt 里只放一次：`compactMessages` 会压缩中段，system 首条虽保留但 provider 侧截断时最先丢的是头；每轮重注保证判据永远在最近窗口内。代价是每轮多 ~150 token，长任务可接受（判据是保命信息）。
- `TaskPlan.describe()` 的现有注入保留，两块并存：任务书是"做到什么算完"，计划是"怎么走"。

## 五、终审判据绑定

- `Supervisor` 新增重载：`review(client, goal, workerSaid, history, finalScreen, finalShot, TaskBook book)`；旧签名保留（book=null 时走老路）。
- prompt 追加段：

```
本次任务书：对象=…；动作=…；完成判据=…（只认这一条）。
裁决铁律：只按上面这条完成判据裁决，不按"做了多少步/有没有进展"裁决；
判据无可观测证据 → completed=false。
```

- 输出 JSON 加 `criterion_met`（判据是否达成，true/false），`completed` 必须与它一致（防模型嘴上说判据没达成、结论却写完成）。
- `AgentLoop.finalReview` 把 book 传进去；`MainActivity` 的终审调用点同步。

## 六、停止线：从任务书长出来

- 每轮动作执行后（现有 `hasClaimEvidence` 检查点旁），加通用检查：`book.checkStop(screenText, historyTail)` → 命中某条 stopLine.signal 即注入系统提示"…按任务书收尾"，并置 `stopLineFired=true`。
- `stopLineFired` 后：模型再调工具超过 2 次 → 强制截停收尾（p2"领取硬停止线"的一般化，原来只认领取成功字样，现在认任务书的 signal）。
- 旧的 `hasClaimEvidence`/`hasUpsell`/`adBudget` 硬编码保留为兜底（book 生成失败/字段空时），不删除——行为不回退。
- 监管者 `intervene` 的领取类特判（"已领取/再看N个→guide 收尾"）保留，v3.50 不动它（那是执行中看门狗，任务书是开跑前，两层都要）。

## 七、低置信拦截：不硬跑，问一句

- 阈值：`confidence < 0.4`（prefs `taskbook_conf_threshold` 可调，默认 0.4）。
- 触发时 `AgentLoop.run()` **不进 runSession**，直接返回澄清态。`run()` 签名保持 `boolean`（兼容旧调用），新增：
- `public boolean needsClarify()`
- `public String clarifyQuestion()`（如"「打开抽屉」是指：①App抽屉设置页 ②家里的抽屉？"+ doubt）
- `public List<String> clarifyOptions()`（2~4 个选项，模型在生成 book 时顺手出 `options` 字段，低置信必填）
- 三端渲染（横扫清单）：
- App（MainActivity）：弹选项对话框，用户点选后把选项文本拼回 goal 重跑（`goal + "（用户明确：" + 选项 + "）"`）。
- TG（TgBot）：发澄清消息带选项，用户回复选项序号/文本后重跑。
- 远控（AgentHttpServer /task）：JSON 返回 `{"needs_clarify":true,"question":"…","options":[…]}`，调用方（云端助手）决定。
- 高置信（≥0.4）但 doubt 非空：不拦截，把 doubt 拼进钉住块末尾当风险提示。

## 八、主人词典 MasterDict（种子版）

- 新类 `MasterDict`，存 `master_dict.json`（与 experience.json 同目录、同读写套路，经 `SharedMemory` 式文件 IO；三端共享天然成立）。
- 结构：`{"items":[{"k":"clash","v":"指 Clash_For_Magisk Magisk 模块（mihomo 内核，给热点下 PC 共享代理），不是 App；启停/升级走模块路径","src":"user"}, …]}`，`src` 标记来源（user=用户亲定，agent=沉淀）。
- v3.50 种子条目（全部来自用户亲定，见 MEMORY）：
1. `clash` → 上述模块定义
2. `领时长/免费听歌` → 汽水音乐走既定技能卡路径（看广告领）、酷狗概念版（com.kugou.android.lite）免广告；领完停止播放并清理后台
3. `完事回桌面` → 铁律：任务完成后 input keyevent 3 回手机桌面
4. `音乐任务收尾` → 停止播放音乐并清理后台
- 注入点两处：①任务书生成 prompt（让模型用词典解指代，如"打开 clash"→对象=Clash_For_Magisk 模块）；②钉住块末尾"主人词典"行（执行期常驻）。
- v3.50 **不做**词典编辑 UI 与自动沉淀（那是 v3.51 认知库的事）；但 `MasterDict.put(ctx,k,v,src)` 接口先留好。

## 十一、验收（SPEC 第六节落 v3.50 的两题）

- clash 词典题："打开 clash" → 任务书对象必须是 Clash_For_Magisk 模块（不是去找 Clash App），判据含模块状态可观测证据。
- 汽水判据题："领汽水免费时长" → 判据="出现领取成功/已领取"；终审只认判据；停止线含链条推销识别。
- 抽屉题留给 v3.53（学习梯子），v3.50 不测。

## 十二、风险与不做事项

- 模型乱填 confidence：prompt 给标尺 + 启发式交叉（关键词命中领取类但 confidence>0.9 且 doubt 为空是正常的，不强制）。
- 每轮 +150 token：判据块做上限裁剪（criteria/stopLines 各 ≤60 字）。
- 不做：词典编辑 UI（v3.51）、技能卡草稿/转正（v3.52）、联网搜索梯子（v3.53）、experience 蒸馏（v3.51）。
- 热补丁不装核心回路：v3.50 整包，补丁通道不动。
